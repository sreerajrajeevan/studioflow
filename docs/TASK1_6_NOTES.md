# Task 1.6 — Flutter migration: implementation notes (2026-11-22)

## What was delivered
- Kotlin app preserved untouched in `legacy-android/` (with
  `README-LEGACY.md`); Flutter app in `flutter_app/` is the product going
  forward. Decision record: `docs/MIGRATION_TO_FLUTTER.md`.
- Stack: Flutter 3.50.0 / Dart 3.14.0, Riverpod 2.6, GoRouter 14.8,
  Material 3 + custom design system. Drift/SQLite and Dio are declared
  for the persistence/API tasks; demo state is in memory by design.
- All 9 destinations as working prototype screens with clearly badged
  SAMPLE data; expanded/medium/compact adaptive layouts; white-label
  branding drives the theme live from Settings; role preview (Owner/
  Staff) labelled as a UI preview, not authentication.

## Correctness core (release-blocking priority 1)
- One money engine (`lib/core/money.dart`): integer paise, half-up
  rounding once per bill, fixed order subtotal → % discount → flat
  discount → tax on discounted amount, discounts clamped at subtotal,
  hard validation caps that throw.
- Cart lines snapshot name + price at first add; catalog price changes
  never alter an open bill (proven by test).
- Draft ids: timestamp + per-process monotonic sequence +
  `Random.secure()` (fixed 2026-11-22 with Sree's approval — the original
  timestamp-only scheme produced only 4,530 unique ids in 5,000 rapid
  calls; the fix yields 5,000/5,000, test-proven).
- Checkout is single-flight: duplicate completions are ignored, a failed
  completion retries the same draft id.
- DEMO QR placeholder only; no real payment QR, no success claim without
  confirmation (the demo dialog states plainly that no payment was
  received).

## Verification (real runs, 2026-11-22)
- `flutter pub get`: 55 dependencies resolved.
- `flutter analyze`: 0 errors, 0 warnings; 17 info notices (13 are
  Flutter 3.50's deprecation notice for the material.dart import — an
  SDK-transition item, not an app defect; 4 const suggestions fixed).
- `flutter test`: **55/55 passed** — money/rounding/validation, cart,
  100 rapid selections, repeated taps, 50-line cart, 150-service search
  filter, snapshot pricing, rotation-keeps-cart, duplicate checkout,
  layout at tablet landscape/portrait + phone, staff-preview hiding,
  dynamic branding, golden screenshot comparisons.
- Screenshots: 8 renders in `flutter_app/screenshots/`, produced by the
  Flutter test engine from the real app widgets with the real Roboto and
  Material Icons fonts loaded. They are renders, not device screenshots.
- APK: **not built in the sandbox.** The Android SDK was completed
  (platform-tools + licenses), but the Gradle wrapper download fails on
  the sandbox's Java network restriction (SSL broken pipe; the Gradle
  daemon's localhost TCP is likewise blocked — see AGENTS.md). Build on
  a developer machine or CI:
  `cd flutter_app && flutter build apk --debug`
  (JDK 17 + Android SDK 36; applicationId `com.dpoise.studioflow`).

## Bugs found & fixed during verification
1. Draft-id uniqueness under rapid creation (above).
2. Staff role preview trapped the user: the rail's "More" button (which
   hosts the role switch) disappeared when staff had no extra
   destinations. The button is now always shown. Caught by the widget
   test, fixed in the app, test green.

## Known limitations of this build
- No persistence: cart, attendance marks, branding edits live for the
  session only. Draft durability across crashes is a persistence-task
  requirement (Drift), tracked in BILLING_CORRECTNESS.md.
- Performance budgets are targets, unmeasured on hardware
  (PERFORMANCE_REQUIREMENTS.md).
- `flutter create` could not run in the sandbox (service restarts); the
  Android scaffold was generated by hand from the Flutter 3.50 SDK's own
  templates (AGP 9.3.1, Kotlin 2.4.20, Gradle 9.5.0) and is identical in
  structure to the tool's output.
